# 项目规则

除非我要求，否则禁止动任何布局和字体、页面比例。

已经确定的背景图片、图标等视觉资源，除非用户明确要求，否则禁止做任何改动。

## 最高优先级视觉基准

- 全页面字体大小、图标大小、控件高度和页面密度的永久基准为 `docs/decisions/2026-05-28-全页面字体图标比例冻结基准.md`。
- 未来所有开发都必须按该文档保持尺寸不变；除非用户明确要求“修改基准”，否则功能开发、Bug 修复、打包、定时器和接口开发都不得改变字体、图标和控件比例。
- 所有页面的字体大小、图标大小、控件高度和页面密度，必须以信用报告页面当前确认版本为基准。
- 新增页面或改页面时，不能单独放大字号、图标或卡片比例；必须先对照信用报告页的 `cqw` 比例体系，再做局部微调。
- 如果用户指出“字体又有问题”“图案比例不一致”，优先检查该页面是否脱离信用报告页比例基准，而不是继续局部放大或缩小单个元素。

## 通用原则

- 用户已明确确认“当前首页布局完美”后，应将该版本视为当前视觉基线，后续改动默认是基于该基线做局部优化，而不是重新设计。
- 视觉问题优先先判断是资源问题、容器问题还是缓存/热更新问题，不要混在一起改。
- 对单个图标的视觉例外，优先做资源级修正或局部样式修正，不扩大到整组公共规则。
- 每次用户确认某个页面“目前正确”后，必须回写项目文档，避免下一轮继续试错。

## 前端验证规则

- 对 `/mnt/d/Ax/code/payapp2` 的前端样式或静态资源改动，不能只相信 Vite 热更新。
- 在 WSL 的 `/mnt/d` 挂载盘上，`vite` 可能漏读最近一次修改；当页面效果与本地文件不一致时，先检查 dev 服务实际返回的源码，再决定是否重启服务。
- 当图标、图片或样式涉及浏览器缓存风险时，应通过版本号查询参数或重启 dev 服务强制刷新验证。

## APK 输出规则

- 以后新打出来的 APK 统一放到项目目录 `/home/zyw/zywFile/payapp2/apk/`。
- 不再默认输出到 Windows 下载目录；只有用户明确要求时，才额外复制到 `C:\Users\12196\Downloads\`。
- 每次给用户 APK 路径时，优先给项目内 `apk/` 目录下的文件。
- 只要本轮改动涉及 APK 真机验收页面或交互，默认流程不是停在源码或浏览器预览，而是必须实际安装到当前已连接手机再交付。

## 首页图标规则

- 首页服务宫格图标必须满足：完整显示、视觉居中、位置一致。
- 首页服务宫格图标当前标准资源目录为 `public/assets/service-icons-normalized/`。
- 图标主体存在明显透明留白差异时，先统一到标准画布后再进入页面使用。
- `政府促消费`、`赚钱中心` 允许保留单独微调，不强行纳入完全统一的自动居中算法。

## 文档维护规则

- 核心代码职责维护在 `docs/file_index.md`。
- 阶段性交接维护在 `docs/handover.md`。
- 稳定视觉结论维护在 `docs/decisions/`。
