## 风险点

- 正常 Gradle 打包会自动同步 WebView assets；如果绕过 Gradle 或手动替换 APK 内容，仍需确认 `dist -> app/src/main/assets/www` 已同步。
- 如果后续直接改 `App.jsx` 内联页面而不改独立组件，信用报告逻辑会再次变得难维护。
- 当前前端常量直接依赖 `9724` 端口的文件直链；如果服务端文件名、端口或 Nginx 路由变化，需要同步更新前端常量。
- 后续新增本地图片时必须走 `assetPath()`，否则浏览器正常但 APK 会丢图。
- 竖屏限制属于 Android 壳层能力，不能只靠 React/CSS 处理；如后续新增 Activity，也需要同步声明 `android:screenOrientation="portrait"`。
- PDF.js 在旧 Android WebView 中必须同时兼容主线程和 worker 线程；不要只在 `index.html` 给主页面补 API 后继续引用普通 `pdfjs-dist/build`。
- 底部 Tab 栏必须作为页面壳层的固定底部区域存在，内容区单独滚动；不要再用全局 `position: fixed` 依赖浏览器视口定位。
- 静态 assets 里的 txt 不能被 WebView 前端直接写入；查询生成记录必须通过 Android 原生内部文件桥接写入，浏览器只能用 localStorage 兜底。
